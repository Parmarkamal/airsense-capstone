2. The Real-World Problem

Air pollution kills 7 million people every year. India has 14 of the world’s 20 most polluted cities. Yet a normal person only sees a raw AQI number – they don’t know:

  • What the number means for their specific health (asthma, child, elderly)
  • Whether tomorrow morning will be safer or worse
  • What simple actions they can take right now

AirSense changes that. It turns raw sensor data into personalised, forward-looking, private health advice – entirely on a laptop, without the internet after initial data pull.

4. Hardware Reality & RAM Budget

WSL2 memory cap (NON-NEGOTIABLE): Before touching Docker, you must create C:\Users\YourName\.wslconfig with memory=3GB and restart WSL. This caps the VM at 3 GB.

Component RAM Allocation
Windows 11 + background ~3.5 GB
WSL2 VM (capped) – TimescaleDB ≤ 3.0 GB
ZooKeeper + Kafka (JVMs tuned) ~1.2 GB
Python (consumer + Streamlit + LangChain) 1.5–2.5 GB
Ollama + phi3:mini loaded ~1.5 GB system + ~2.5 GB VRAM
VS Code + Chrome 1.5–2.5 GB
Peak Total (Demo Conditions) ~11.5–13.5 GB

Safety Net: Increase the Windows pagefile to 8–16 GB to prevent crashes if memory spikes.

6. 12-Week Roadmap (Precise, Week-by-Week)

PHASE 1 – DATA FOUNDATION (Weeks 1-2)

Week 1 – Live Data Flows into Kafka

  • Register free WAQI token. Create Kafka topic aqi_raw.
  • Write Python script fetch_aqi.py to call WAQI API and publish JSON to Kafka.
  • Schedule script in Windows Task Scheduler (hourly).
✓ Checkpoint: Open Kafka console consumer – see new AQI messages arriving hourly.

Week 2 – Clean Data Accumulates in TimescaleDB

  • Create .wslconfig. Start TimescaleDB via Docker Compose.
  • Create hypertable aqi_readings.
  • Write Python Kafka consumer with Pydantic validation to insert valid rows into DB.
✓ Checkpoint: Run SQL query – rows grow every hour.
PHASE 2 – VISUALISATION (Weeks 3-4)

Week 3 – First Live Dashboard

  • Build Streamlit app: City selector, AQI gauges, 24-hour line chart.
  • Set auto-refresh to 60 seconds.
✓ Checkpoint: Open localhost:8501 – live gauges update automatically.

Week 4 – Insights & India Map

  • Jupyter EDA: Diurnal patterns, Z-score spikes.
  • Add Folium interactive India map to Streamlit.
✓ Checkpoint: Map shows red/orange/green bubbles. Click city for AQI.
PHASE 3 – FORECASTING (Weeks 5-6)

Week 5 – Train the ML Model

  • Engineer lag features, rolling means. Train LightGBM with walk-forward validation.
  • Log to MLflow. Save 48-hour forecasts to DB.
✓ Checkpoint: MLflow UI shows run; RMSE < 30 AQI units.

Week 6 – Forecast Appears on Dashboard

  • Add chart combining actual AQI (solid) and predicted (dashed).
✓ Checkpoint: Chart clearly shows where AQI is heading next 48 hours.
PHASE 4 – AI HEALTH ADVISOR (Weeks 7-8)

Week 7 – Build the Knowledge Base

  • Chunk WHO/CPCB PDFs. Embed with MiniLM. Store in ChromaDB.
✓ Checkpoint: Test query returns relevant WHO paragraphs.

Week 8 – Safe, Grounded AI Chat

  • Build LangChain agent with tools: Get AQI + Search Guidelines. Connect to Ollama (phi3:mini).
  • Add strict system prompt (no diagnoses, must cite).
✓ Checkpoint: AI gives cited, offline answers with medical disclaimers.
PHASE 5 – POLISH & REPORTS (Weeks 9-10)

Week 9 – Professional Unified App

  • Organise Streamlit tabs. Add AI kill-switch and disclaimers.
✓ Checkpoint: App is polished; kill-switch disables AI seamlessly.

Week 10 – Power BI Executive Reports

  • Connect Power BI to TimescaleDB. Create DAX measures.
✓ Checkpoint: Two-page executive report fully functional.
PHASE 6 – AUTOMATION & DEMO HARDENING (Weeks 11-12)

Week 11 – MLOps & Phone Alerts

  • Python retraining script (champion-challenger) scheduled weekly.
  • Telegram bot for AQI spike alerts.
✓ Checkpoint: Manually trigger spike – phone buzzes.

Week 12 – Stress Test & Demo Prep

  • 24-hour test. Test backup scenarios. Create start_demo.bat.
✓ Checkpoint: System survives all failure tests; ready for defense.

8. Demo Day Backup Strategy (3 Layers)

  1. Internet down / API fails: Click "Replay Mode". Pre-loaded 7-day CSV feeds Kafka. System works identically.
  2. Ollama crashes / OOM: Toggle kill-switch. Chat hides, dashboard survives. Show pre-generated chat screenshots.
  3. Docker fails: Show static dashboard/Power BI screenshots and play a 5-minute pre-recorded demo video.
