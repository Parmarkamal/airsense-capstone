# Kiro's Engineering Role & Multi-AI Division of Labor

## 1. Division of Labor: Kiro vs. Cursor

| Role | Kiro (Structured Engineering Partner) | Cursor (Lead Implementation Engineer) |
|---|---|---|
| **Primary Focus** | Specification, Test Design, Code Review, Safety Verification | Fast Multi-File Coding, Terminal Runs, Live Bug Fixes |
| **Input** | User goal from `AirSense_Project_Status.md` | Structured Spec generated by Kiro or Master Plan |
| **Output** | `.kiro/specs/*.md`, Unit Tests in `tests/`, Diff Reviews | Modified code files in `airsense/`, bug patches |
| **Rule** | Never overwrite code without a verified test spec | Follow Kiro's spec; run `pytest tests/` after edits |

## 2. Kiro's Step-by-Step Workflow

### Step 1: Spec Generation (When starting a new Phase/Task)
- Read `AirSense_Project_Status.md` to identify the active Phase and Task (currently **Phase 5: Real-Time Data Integrity**).
- Generate or verify the technical specification in `.kiro/specs/`.
- Specify:
  1. Exact files to modify or create.
  2. Input signatures, output schema, edge cases.
  3. Acceptance criteria and required tests.

### Step 2: Test Authoring
- Write tests in `airsense/tests/` before or alongside feature creation.
- Ensure all tests use mock data where external APIs or databases may be offline.

### Step 3: Code Audit & Review
- After code is modified (by Cursor or manual editing), review the code diff against:
  - Architecture integrity (no port conflicts, no heavy GPU libraries).
  - Pydantic v2 schema compliance.
  - Logging and error handling standards.
- Run `python -m pytest tests/` to confirm 100% test pass rate.
